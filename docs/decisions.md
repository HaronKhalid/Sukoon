# Decisions
1. **Fokus chosen as base** (2026-11-12): modern stack, builds config current (AGP 9.4.1, targetSdk 36), tests, CI, Hilt/Room, notes/fonts/pomodoro/usage already present. Victoria is smaller/older.
2. **Name Sukoon**, applicationId `io.github.haronkhalid.sukoon`; Kotlin namespace unchanged.
3. Started as a clone of Fokus 1.9.8 (commit 019ba80). On 2026-11-20 the published history was replaced by one fresh commit so the repository shows only Sukoon authorship; upstream credit is kept in README, AUTHORS, LICENSE, file headers and the in-app acknowledgements. The original history remains available at https://github.com/luantak/FokusLauncher.
4. **Theme engine** (Milestone 2): data-only, versioned (`schemaVersion` 1) theme model in `com.lu4p.fokuslauncher.theme`; stored in the existing launcher DataStore (selected id + custom themes JSON, max 20). Own strict pure-Kotlin JSON reader (no org.json/serialization dependency; identical behaviour in JVM tests): rejects malformed/oversized/too-deep input, bad hex, bad ids, unreadable contrast, future schema versions; unknown keys ignored, never executed; imported themes always get a fresh id. No theme selected = legacy Fokus look (visual styles keep working); an applied theme overrides the neon visual style, and is ignored over photo wallpapers. Settings pages use `themedSettingsScrim` instead of hard-coded black so light themes stay readable.

## Milestone 3: typography and notes
- **Per-element fonts live in their own DataStore** (`typography_preferences`, one string per element: clock, date, app labels, notes), not in `PreferencesManager`, to keep shared files untouched. Empty value = follow the existing launcher-wide font, so current behaviour is the default. Value grammar extends the existing one: `""`, system family name, `custom:<file>` (existing import), new `bundled:<id>`.
- **Bundled fonts are variable TTFs loaded from `assets/`** through Compose `Font(path, assets, variationSettings)` for weights 300-700 (minSdk 26 supports variation settings). One variable file per family keeps the APK delta small versus static weights. Resolved `FontFamily` objects are cached per stored value in a singleton (`FontFamilyCache`); failures fall back to the launcher font.
- **Elements applied through a CompositionLocal** (`LocalElementFonts`, provided once around the NavHost) and a `TextStyle.withElementFont(element)` one-liner at the clock, date, home favourite label and drawer label call sites. No per-recomposition font loading.
- **Notes use Room, table `notes`, database version 7 -> 8** (additive `CREATE TABLE`, `MIGRATION 7->8` in `AppModule`). Existing SAF-markdown home note is untouched; when an in-app note is pinned it replaces the SAF note in the home note slot, otherwise the SAF note renders as before.
- **"Pin" and "displayed" are one concept**: exactly one pinned note is shown on the home screen (pin is made atomic by a `@Transaction`). The home note toggle in Home widgets settings still governs whether the slot shows.
- **Safe save**: editor draft is held in `SavedStateHandle` (survives process death), autosaved to Room 400 ms after each keystroke, flushed on `ON_STOP`/back, and a restored draft is written back on ViewModel start. Late saves for deleted notes are ignored; a blank new note is discarded on close.
- **Mixed-direction**: note text uses `TextDirection.Content` (per-paragraph first-strong rule) with logical Start/End alignment; line height is a multiple of font size with `Trim.None` so Nastaliq ascenders/descenders are not clipped. `BidiText` holds pure helpers for tests.
- Jameel Noori Nastaleeq is deliberately not bundled (no confirmed licence).
5. **Layout and clock config as versioned text in the existing DataStore** (Milestone 2): `home_layout_config_v1` and `clock_studio_config_v1` are compact pipe-delimited strings (codec in `home/layout`), not JSON, so they are unit-testable on the plain JVM and fit the backup system's typed string preferences without schema changes. Invalid or unknown data decodes to null and the repository falls back to defaults; the default config reproduces the pre-existing home screen (all current elements visible, app search / focus status / spacer off).
6. **Presets are plain configurations** (`HomeLayoutConfig.forPreset`); any edit flips the preset label to CUSTOM. No separate preset code path.
7. **Home integration is additive**: `HomeLayoutViewModel` supplies a `LocalHomeLayout` CompositionLocal read inside `HomeWidgetsSection`/`HomeClockWeatherHeader`, so `HomeViewModel` and composable signatures are unchanged. The legacy `ClockWidget` is still used when clock settings are default.
8. **Clock ticking**: `ConfiguredClock` ticks once per minute (aligned to the minute boundary), and once per second only when seconds are enabled. The existing 1 s ViewModel ticker is untouched (it only emits on change).
